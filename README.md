# 木版年画刻版工序档案

## 项目简介

面向木版年画作坊的纯前端工序档案应用。它把画稿、分版、刻版、修版与套色印制过程串成可追溯的本地记录，便于刻工与印制管事按套色序号协作。

## Docker 一键启动

首次启动先复制环境配置，再构建并启动容器：

```bash
cp .env.example .env && docker compose up -d --build
```

停止服务可执行：

```bash
docker compose down
```

## 数据存储说明

数据全部写入浏览器 IndexedDB，不依赖后端服务。数据库名为 `gbwoodprint-db`，当前结构版本为 `3`。

- `version(1)` 建立画稿、版片、刻工、印制批次、工序节点五张表及常用查询索引。
- `version(2)` 为各表回填 `schemaRev: 2`，便于后续迁移识别数据结构。
- `version(3)` 引入追加式版次，新增三张表：
  - `blockRevisions` 版次表：返修只追加新版次，每条冻结当时的版片摘要（木料、版厚、状态、备注等）、改刀原因、操作人与是否换木料；旧版次永不被后来状态覆盖。`[blockId+revNo]` 复合唯一索引保证同版版次号不重复。
  - `printRuns` 逐版印次表：批次登记时逐版落印次，记录落印时版次、原印次数量与套色偏差；按新刀口重打另存新印次并与原印次互相挂接，原印次与偏差原样保留。
  - `blockReviews` 复核结论表：可“沿用旧印样”或“重打”，复核针对的是改刀后的当前版次。
  - 工序节点新增 `revNo` 归属，旧节点留在原版次；版片一改，用到它的已登记批次（存在落后版次印次）即派生为“待复核”，没碰到该版的批次不受影响。
  - 返修追加、批次登记、复核/重打均在单个 IndexedDB 事务内完成，任一步失败整笔回滚；返修单与复核单草稿暂存 `localStorage`，失败或重开后可继续提交。
  - 老数据升级（v2 → v3）时：按现有工序节点为每块版补第 1 版，**来源缺失一律记为“未知”，不据旧备注反推历史**；旧节点归属第 1 版；旧批次按该画稿现有版片补推断印次（标注“迁移推断”、逐版偏差拆不出则留空），批次总检原文保留。
- 首次创建数据库时通过 Dexie 的 `populate` 回调写入四类画稿、完整基础版片（含首版与既有返修版次）、四名刻工、印制批次（含逐版印次）与多条工序节点。
- 刷新页面不会丢失数据；清除浏览器站点数据会同时清除本地档案。

## 核心功能与路由表

| 路由 | 页面 | 主要能力 |
| --- | --- | --- |
| `/drafts` | 画稿总览 | 按题材与状态筛选，查看版片刻成进度和最近印制批次，内联新建画稿 |
| `/drafts/:id/blocks` | 版片编排台 | 按套色序号排列表格，指派刻工、校验序号、标记刻成；返修以“追加新版次”登记改刀原因与换木料，并查看每版当时摘要 |
| `/blocks/:id/nodes` | 工序节点时间线 | 节点按版次分组；给当前版次推进/回退节点，旧版节点作为历史保留 |
| `/batches` | 印制批次登记 | 登记纸张、颜料、印数，逐版按当前版次填写套色偏差；改刀后对待复核印次沿用旧印样或按新刀口重打（另存） |
| `/carvers` | 刻工档与版片分布 | 按专长筛选，查看在刻版片数、节点平均耗时与当班分布 |
| 其它 | 画稿总览 | 已实现 history 路由到画稿总览的回退 |
